1. 시스템 개요

이 패키지는 Livox LiDAR와 IMU로 Super-LIO SLAM을 실행하고, 로봇 정면의 수직 평면(벽/장애물 면)에 대한 상대 각도와 거리를 ROS 2 토픽으로 발행합니다.

구성역할
Livox Driver2MID360 또는 MID360S의 LiDAR/IMU 데이터를 ROS 2로 발행합니다.
Super-LIOLiDAR-IMU odometry 및 SLAM 자세를 계산합니다.
전방 벽 추정기정면 ROI의 수직 평면을 RAW와 짧은 로컬 서브맵으로 추정해 안정적인 최종값을 발행합니다.
상태 모니터INIT, 벽 검출 상태, 위치/속도, roll/pitch/yaw를 터미널 표로 표시합니다.
벽 각도 0°는 로봇 정면이 벽과 수직인 상태입니다. 설치 오차, 움직임, 비평면 물체는 실제 정확도에 영향을 줄 수 있습니다.

3. 설치 및 빠른 시작

3.1 패키지 설치

전달받은 DEB 파일을 대상 장비에 복사한 뒤, 파일이 있는 폴더에서 실행합니다.

sudo apt install ./cocelo-hd-slam-yaw_0.7.2-1+humble22.04_arm64.deb
dpkg -s cocelo-hd-slam-yaw | grep -E 'Status|Version|Architecture'
autonomy-slam --help

설치 후 수정하는 설정 파일은 다음 한 곳입니다.

sudoedit /etc/cocelo/cocelo-hd-slam-yaw/autonomy_light.yaml

3.2 최초 기동

  1. LiDAR 전원, Ethernet 케이블, IMU 연결 상태를 확인합니다.
  2. 다음 절의 LiDAR 모델·IP·NIC 이름을 현장 장비 값으로 맞춥니다.
  3. 로봇 정면을 초기 기준 벽에 가능한 수직으로 맞추고 정지시킵니다.
  4. 실행합니다.
autonomy-slam --real

종료는 실행 터미널에서 Ctrl+C를 누릅니다.

4. LiDAR 모델·네트워크 설정

물리 LiDAR 관련 값은 모두 설치 설정 파일의 livox: 블록에서 관리합니다.

이 블록은 Livox Driver2와 Super-LIO가 함께 사용합니다. Driver2는 model/IP/UDP 소켓을 사용하고, Super-LIO는 같은 설정에서 전달된 CustomMsg·IMU 토픽과 모델·IP 진단 파라미터를 사용합니다. 즉 IP를 두 곳에 따로 설정할 필요가 없습니다.

4.1 MID360 예시

livox:
  model: "mid360"
  interface: "enP8p1s0"
  host_ip: "192.168.1.50"
  lidar_ip: "192.168.1.166"

4.2 MID360S 예시

livox:
  model: "mid360s"
  interface: "<LiDAR가 연결된 NIC 이름>"
  host_ip: "<PC NIC IP>"
  lidar_ip: "<MID360S에 설정된 IP>"
host_ip를 YAML에 적는 것만으로 PC NIC IP가 바뀌지는 않습니다. 운영체제의 NetworkManager, netplan 또는 현장 네트워크 절차로 먼저 NIC에 IP를 설정해야 합니다. 프로그램은 기동 시 정확한 NIC/IP 조합이 있는지만 검사하며 네트워크를 자동 변경하지 않습니다.

4.3 네트워크 확인

ip -o -4 addr show dev enP8p1s0
# 출력된 IP가 YAML의 livox.host_ip와 같아야 합니다.

기동 로그에 Livox: model=... interface=... host=... lidar=...가 표시되면 선택된 설정값이 확인된 것입니다.

5. 초기 정렬과 정상 운전

기본 설정은 잘못된 초기 yaw를 방지하기 위해 INIT 단계를 사용합니다.

  1. 로봇을 최초 정면 벽에 거의 수직으로 둡니다.
  2. INIT 표의 MEAN이 목표 0.00 +/- 1.00 deg 이내가 되도록 방향을 조정합니다.
  3. 충분한 유효 프레임이 쌓이면 INIT ACCEPTED가 표시됩니다.
  4. 임시 SLAM은 종료되고, 정렬된 자세에서 새 map/yaw로 운영 SLAM이 자동 시작됩니다.
INIT가 승인되기 전에는 최종 벽 각도를 발행하지 않습니다. 초기 기준 yaw가 틀어진 상태로 시작하는 것을 막기 위한 정상 동작입니다.

INIT가 오래 걸리면 정면에 충분히 넓은 수직 벽이 있는지, 로봇이 정지했는지, LiDAR/TF가 정상인지 확인하십시오. require_initial_alignment: false로 우회할 수 있지만 초기 yaw 정렬 보호도 꺼집니다.

6. 출력 토픽과 값의 의미

토픽형식용도
/autonomy_light/front_wall_angleautonomy_light/msg/WallAngle최종 전방 벽 각도·거리·검출 사유·RAW/SUBMAP 진단값
/autonomy_light/slam_anglestd_msgs/msg/Float64SLAM yaw를 90° 기준으로 접은 별도 보조값. FINAL 벽 각도는 바꾸지 않습니다.
/autonomy_light/front_wall_roisensor_msgs/msg/PointCloud2추정기에 입력된 정면 ROI 점군. RViz 점검용
/lio/global_mapsensor_msgs/msg/PointCloud2기본 활성화된 누적 Super-LIO 맵. map 프레임, 약 1 Hz, 마지막 맵 보존 QoS
/lio/odomnav_msgs/msg/OdometrySuper-LIO 위치·속도·자세

ros2 topic echo --once /autonomy_light/slam_angle

ros2 topic hz /autonomy_light/front_wall_angle
필드의미
detectedtrue일 때 최종 각도·거리가 유효합니다. false면 수치 필드는 NaN일 수 있으므로 사용하지 마십시오.
relative_angle_deg최종 상대 벽 각도[deg]. 0°는 정면이 벽과 수직인 상태입니다.
distance_m추정 평면까지의 수직 거리[m]입니다.
angle_stddev_deg한 스캔의 기하학적 1-sigma 추정치입니다. 외부 캘리브레이션 오차까지 보장하지는 않습니다.
estimate_sourceRAW, SUBMAP, 호환 융합 또는 RAW_CONFLICT입니다. 벽이 바뀌면 RAW_CONFLICT가 정상적으로 나타날 수 있습니다.
detection_reason초기화 중, TF 없음, ROI 점 부족, 평면 불충족 등 미검출 원인입니다.

slam_angle은 SLAM yaw의 90° 기준 나머지입니다. 예: +93°→+3°, +88°→-2°. 벽 검출 실패 시 상위 제어기가 참고할 보조 토픽이며 FINAL 벽 각도와 혼합되지 않습니다.

/lio/global_map은 기본 ./launch.sh에서도 발행됩니다. RViz2 Fixed Frame을 map으로 지정하고 PointCloud2 디스플레이에 이 토픽을 선택하십시오. 이것은 라이브 ROS 토픽이며, PCD 파일 저장은 별도 lio.map.save_map 설정입니다. 이를 true로 바꾸면 기본 save_interval: -1에 따라 종료 시 같은 누적 맵을 한 번 저장합니다.

8. 문제 해결

증상원인과 조치
livox.host_ip ... is not assignedYAML의 interface/host_ip와 실제 NIC가 다릅니다. ip -o -4 addr show dev <NIC>로 확인한 뒤 OS 네트워크 설정 또는 YAML을 맞춥니다.
LiDAR 데이터가 안 들어옴전원·케이블·IP 대역을 확인합니다. PC와 LiDAR가 같은 서브넷인지, 방화벽이 UDP를 막지 않는지 점검합니다.
INIT가 계속 LOCKED정면에 넓은 수직 벽을 두고 로봇을 수직에 가깝게 맞춥니다. ROI, TF, LiDAR 점군 유입을 확인합니다.
wall=not-detectedROI에 유효 수직 평면이 없거나 점 수/폭/높이 조건을 만족하지 못한 것입니다. detection_reason, roi_point_count, required_inlier_count를 확인합니다.
각도가 흔들림LiDAR-IMU 외부 파라미터와 base_link→LiDAR 장착 변환을 먼저 확인합니다. 다음으로 ROI에 여러 면이 함께 들어오는지 확인하고 ROI/필터를 조절합니다.
각도 부호가 기대와 다름상위 제어기에서 메시지 정의와 base_link 축 방향을 먼저 확인합니다. 센서 장착/TF 축이 뒤집혔는지 점검하고 출력 부호만 임의 반전하지 마십시오.
실행 직후 종료autonomy-slam --help와 dpkg -s cocelo-hd-slam-yaw를 확인합니다. ROS 2 Humble 설치 여부와 터미널의 첫 오류를 확인합니다.

8.1 RViz ROI 점검

  1. RViz2 Fixed Frame을 base_link로 설정합니다.
  2. PointCloud2 디스플레이를 추가합니다.
  3. 토픽으로 /autonomy_light/front_wall_roi를 선택합니다.
  4. 의도한 정면 벽만 ROI에 들어오는지 확인한 뒤 ROI 파라미터를 조정합니다.

9. 업데이트·제거·지원 정보

9.1 업데이트

sudo cp /etc/cocelo/cocelo-hd-slam-yaw/autonomy_light.yaml \
  /etc/cocelo/cocelo-hd-slam-yaw/autonomy_light.yaml.backup
sudo apt install ./새_패키지_파일.deb

설정 파일은 Debian conffile입니다. 이미 수정한 YAML이 있으면 apt가 유지/교체 여부를 물을 수 있으므로 설치 전 백업을 권장합니다.

9.2 제거

sudo apt remove cocelo-hd-slam-yaw
# 설정 파일까지 제거하려면:
sudo apt purge cocelo-hd-slam-yaw

9.3 지원 요청 시 전달할 정보

  • DEB 파일명 및 dpkg -s cocelo-hd-slam-yaw 출력
  • cat /etc/os-release, dpkg --print-architecture 출력
  • 수정된 livox: 블록(비밀번호 등 민감정보 제외)
  • 실행 시작부터 오류 시점까지의 전체 터미널 로그
  • ros2 topic echo --once /autonomy_light/front_wall_angle 결과

문서 끝. 현장 변경은 한 번에 하나의 파라미터 그룹만 바꾸고, 매 변경 후 정지 상태와 주행 상태에서 모두 검증하는 것을 권장합니다.
